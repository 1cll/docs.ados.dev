# Рабочие процессы

Workflows обеспечивают структурированный многоэтапный процесс для ИИ-решения задач: **Plan → Approval → Implement → Review**.

## Обзор

Вместо того чтобы ИИ сразу приступал к изменению кода, Workflows разбивают реализацию на контролируемые этапы:

```
[Plan] → [Approval] → [Implement] → [Review]
```

Это обеспечивает более высокое качество результата и даёт людям контроль над тем, что будет реализовано.

## Этапы

### 1. Plan

ИИ-агент анализирует задачу и генерирует план реализации — без внесения каких-либо изменений в код.

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| Модель | claude-sonnet-4.5 | Модель для планирования |
| Тайм-аут | 10 мин | Макс. время планирования |

План включает:
- Файлы, которые будут изменены
- Подход и обоснование
- Оценка сложности

### 2. Approval (Опционально)

Если включён `require_approval`, план публикуется как комментарий к задаче и ожидает одобрения человеком перед продолжением.

- Человек проверяет план и одобряет или отклоняет его
- Отклонённые планы можно доработать с дополнительными инструкциями

### 3. Implement

ИИ-агент реализует одобренный план — создаёт ветки, пишет код и добавляет тесты.

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| Модель | Модель репозитория по умолчанию | Модель для реализации |
| Тайм-аут | 30 мин | Макс. время реализации |

### 4. Review

Другая модель ИИ проверяет реализацию на корректность, лучшие практики и соответствие плану.

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| Модель | gpt-5.1 | Модель для ревью |
| Тайм-аут | 10 мин | Макс. время ревью |

Вердикты ревью:
- **PASS** — Реализация корректна, PR создаётся
- **NEEDS_REVISION** — Обнаружены проблемы, отправлено на доработку
- **FAIL** — Фундаментальные проблемы, требуется вмешательство человека

## Конфигурация

Включите workflows в настройках репозитория:

```yaml
repos:
  - name: my-repo
    workers:
      issue_watcher:
        enabled: true
```

Поведение workflow можно настроить для каждого репозитория на странице **Workflow** в панели управления, где вы можете задать этапы ADOS pipeline и модели.

## Использование в панели управления

1. Перейдите на вкладку **Workflow**
2. Настройте этапы ADOS pipeline для вашего репозитория
3. Задайте модели и тайм-ауты для каждого этапа
4. Включите/выключите точки одобрения

## Статусы рабочих процессов

Каждое выполнение workflow отслеживается в Firestore и может быть просмотрено из панели управления:

| Статус | Описание |
|--------|----------|
| `planning` | Генерируется план |
| `awaiting_approval` | Ожидает одобрения человеком |
| `implementing` | Код реализуется |
| `reviewing` | Реализация проверяется |
| `completed` | Все этапы пройдены успешно |
| `failed` | Workflow завершился с ошибкой на одном из этапов |

> [!TIP]
> Использование разных моделей ИИ для планирования, реализации и ревью может повысить качество за счёт разных перспектив.
