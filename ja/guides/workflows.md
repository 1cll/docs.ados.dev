# ワークフロー

ワークフローは、AI による Issue 解決を構造化されたマルチステージプロセスで実行する機能です：**Plan → Approval → Implement → Review**。

## 概要

AI がいきなりコード変更に取り掛かるのではなく、ワークフローは実装を制御されたステージに分割します：

```
[Plan] → [Approval] → [Implement] → [Review]
```

これにより、より高品質なアウトプットが得られ、何が実装されるかを人間がコントロールできます。

## ステージ

### 1. Plan

AI エージェントが Issue を分析し、実装計画を生成します — コード変更は行いません。

| 設定 | デフォルト | 説明 |
|------|---------|------|
| モデル | claude-sonnet-4.5 | 計画用モデル |
| タイムアウト | 10 分 | 最大計画時間 |

計画には以下が含まれます：
- 変更対象のファイル
- アプローチと理由
- 推定の複雑度

### 2. Approval（オプション）

`require_approval` が有効な場合、計画が Issue のコメントとして投稿され、処理を進める前に人間の承認を待ちます。

- 人間が計画をレビューし、承認または却下します
- 却下された計画は追加の指示とともに修正できます

### 3. Implement

AI エージェントが承認済みの計画を実装します — ブランチの作成、コード記述、テストの追加を行います。

| 設定 | デフォルト | 説明 |
|------|---------|------|
| モデル | リポジトリのデフォルトモデル | 実装用モデル |
| タイムアウト | 30 分 | 最大実装時間 |

### 4. Review

実装の正確性、ベストプラクティスへの準拠、計画との整合性を別の AI モデルがレビューします。

| 設定 | デフォルト | 説明 |
|------|---------|------|
| モデル | gpt-5.1 | レビュー用モデル |
| タイムアウト | 10 分 | 最大レビュー時間 |

レビュー結果：
- **PASS** — 実装は良好、PR が作成される
- **NEEDS_REVISION** — 問題が見つかり、修正のため差し戻し
- **FAIL** — 根本的な問題があり、人間の対応が必要

## 設定

リポジトリ設定でワークフローを有効化します：

```yaml
repos:
  - name: my-repo
    workers:
      issue_watcher:
        enabled: true
```

ワークフローの動作はダッシュボードの **Workflow** ページからリポジトリごとに設定でき、ADOS パイプラインのステージとモデルを設定できます。

## ダッシュボードでの使い方

1. **Workflow** タブに移動
2. リポジトリの ADOS パイプラインステージを設定
3. 各ステージのモデルとタイムアウトを設定
4. 承認ゲートの有効/無効を切り替え

## ワークフローの状態

各ワークフロー実行は Firestore で追跡され、ダッシュボードから監視できます：

| ステータス | 説明 |
|-----------|------|
| `planning` | 計画を生成中 |
| `awaiting_approval` | 人間の承認を待機中 |
| `implementing` | コードを実装中 |
| `reviewing` | 実装をレビュー中 |
| `completed` | すべてのステージが正常完了 |
| `failed` | いずれかのステージで失敗 |

> [!TIP]
> 計画、実装、レビューに異なる AI モデルを使用すると、多様な視点が得られ、アウトプットの品質が向上します。
